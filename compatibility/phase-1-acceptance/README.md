# Phase 1 Public Acceptance Records

This directory is the public, credential-free Phase 1 acceptance boundary owned by the reference
harness. The sole schema is `mirror-control.schema.json`, generated by
`public-record-schema.ts`. Committed schema bytes must equal the deterministic generator output.

The public record contains the shared non-private acceptance roots plus exactly
`asterGovernanceSatisfied: true` and `asterPrivateRecordSha256`. It never contains private Aster
governance, pull-request numbers, reviewer identities, check details, rulesets, authorization data,
credentials, raw logs, or a generic metadata map. `review-candidate` is not a public-record mode.

The four artifact records are required in this exact order:

1. `phase-1-browser.json`
2. `phase-1-candidate-invariants.json`
3. `phase-1-conformance.json`
4. `phase-1-differential.json`

The three conformance adapter IDs are exactly `oidf-basic-1`, `oidf-basic-2`, and `oidf-post-1` in
that order. Mirror control requires 22 differential scenarios and four browser flows with zero
differences, all 18 candidate-invariant controls detected, identical oracle/candidate image digests,
no official result IDs, and this exact statement:

> Mirror control only; this record does not claim Aster runtime compatibility or OpenID Foundation certification.

Runtime candidate uses the same successful counts, requires exactly two sorted unique opaque official
result IDs that are not profile plan names, and uses this exact statement:

> Aster Phase 1 acceptance passed for the pinned profile, schema, harness, images, and evidence.

The lifecycle keeps four measured oracle/candidate primary/foreign stacks pristine. Live Phase 0
provenance reproduction runs on two additional disposable, independently keyed oracle/candidate
stacks and cannot share an endpoint, network, database, Redis volume, or secret with a measured
stack. Private run state defaults below `/var/tmp/henry-build`; CI may select another normalized,
non-system build root with `ASTER_PHASE1_BUILD_ROOT` when that directory already exists, is a real
current-user-owned directory, and has mode `0700`.

The private record/replay oracle snapshot canonicalizes every validated bounded-timestamp envelope
from `{$timestamp, $toleranceSeconds}` to `{$boundedTimestamp: tolerance}`. It therefore pins the
envelope position and declared tolerance, but intentionally does not pin absolute timestamps or
cross-field time offsets. Those raw values remain subject to the same-run oracle/candidate bounded
comparison, while explicit derived fields such as token lifetime and cookie expiry offset remain
exact. The snapshot `projectionSha256` hashes this private canonical value and is intentionally not
interchangeable with a published evidence-envelope hash. Snapshot files recorded before this
canonicalization change must be discarded and recorded again.

JSON Schema closes every object and ordered array. The procedural validator additionally enforces
bytewise ordering, mirror image equality, official-result semantics, and public redaction constraints
that JSON Schema cannot express.
